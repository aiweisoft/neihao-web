# 医疗设备管理系统

基于 **uni-app + uniCloud（支付宝云）** 构建的医疗设备全生命周期管理后台系统。采用 uni-admin v2.5.13 管理后台模板，支持 PC 宽屏与移动端自适应。

## 功能模块

### 🏥 设备管理

设备管理是整个系统的核心基础模块，其他所有业务模块均围绕设备展开。

| 子模块 | 说明 |
|--------|------|
| **设备台账** | 医疗设备 CRUD，支持设备编号、名称、品牌、规格型号、注册证号、采购信息、验收日期、保修年限等字段 |
| **Excel 导入** | 通过云函数解析 xlsx 文件，批量导入设备数据并自动校验字段 |
| **设备分类** | 多层设备分类管理，设备可挂载到分类下 |
| **存放位置** | 设备存放位置管理，设备可关联到具体位置 |
| **使用部门** | 部门管理（基于 opendb-department），设备可指定使用部门 |

**设备状态流转：**
```
正常(1) → 使用中(2) → 维修中(3) → 正常(1)
使用中(2) → 报修 → 维修中(3) → 维修完成 → 使用中(2)
任意状态 → 报废(4)
未投入(5)、其他(6)
```

**删除保护：** 设备存在未删除的报修记录时，禁止删除该设备，需先删除关联报修记录。

---

### 🔧 维修管理

维修管理由 **设备报修 → 维修记录** 两级构成，前者发起报修申请，后者记录实际维修情况。

#### 设备报修

- 报修时只能选择 **状态为使用中(2)** 的设备
- 提交报修后，设备状态自动变为 **维修中(3)**
- 报修单状态：待处理(1) → 处理中(2) → 已完成(3) / 已关闭(4)
- 删除报修记录时，关联设备状态恢复为 **使用中(2)**

#### 维修记录

- 从报修单发起维修（"去维修"按钮），自动带入报修信息和关联设备
- 维修结果：已修复(1) / 部分修复(2) / 无法修复(3)
- 维修完成后（结果=已修复），设备状态自动恢复为 **使用中(2)**
- 删除维修记录时，报修单恢复为 **待处理(1)**，设备状态恢复为 **维修中(3)**

**操作限制：**
- 报修单只能删除关联的维修记录后才能删除
- 设备只能删除关联的报修记录后才能删除

**数据关联路径：**
```
设备台账 ← 设备报修 ← 维修记录
  └── device_id ──→ device_id ──→ device_id
                   └── repair_request_id ──→ repair_request_id
```

> **注：** 本项目与同级目录下的 [device](https://github.com/anomalyco/device) 移动端 App 共享同一数据库。device 端用户可扫码查看设备、发起报修；neihao-web 管理员端处理维修流程，数据互通。

### 📅 保养管理

#### 保养计划

- 为设备制定定期保养计划，支持设置保养周期、提前提醒天数
- 到期后自动关联生成报警提醒

#### 报警提醒

- 由定时云函数 `maintenance-alert-cron` 自动扫描保养计划生成
- 支持保养到期（黄色）、校验到期（蓝色）、维修提醒（红色）等类型
- 已读/未读管理，首页仪表盘高亮展示待处理提醒

**数据关联路径：**
```
设备台账 ← 保养计划 ← 报警提醒
  └── device_id ──→ device_id ──→ device_id
```

**典型流程：**
```
制定保养计划（设置提醒提前天数）
    ↓ [定时云函数每日扫描]
生成报警提醒
    ↓
首页仪表盘显示待处理提醒数
    ↓
管理员处理 → 标记已读
```

### 📊 仪表盘（首页）

首页实时展示以下核心数据：

- **统计卡片**：设备总数、设备分类数、存放位置数、使用部门数、待处理提醒数
- **设备状态总览**：正常 / 使用中 / 维修中 / 报废 / 未投入 / 其他 — 各状态数量及占比进度条，点击可跳转到对应状态筛选列表
- **使用科室设备分布**：环形图展示各科室设备数量（Top 10）
- **设备分类统计**：环形图展示各类别设备数量（Top 10）
- **最近添加设备**：最近 6 条新增设备记录
- **待处理提醒**：未读报警提醒列表
- **快捷入口**：新增设备、设备分类、存放位置、使用部门

每次返回首页时自动刷新设备状态总览和提醒数据。

## 技术栈

| 类别 | 技术 |
|------|------|
| 前端框架 | uni-app（Vue 2/3 双兼容，条件编译） |
| 状态管理 | Vuex（modules: app, user, error） |
| 国际化 | vue-i18n（简体中文、繁体中文、English） |
| UI 组件 | uni-ui 生态（uni-table, uni-forms, uni-easyinput 等） |
| 后端平台 | uniCloud 支付宝云 |
| 云函数 | 10 个云函数（含定时任务、Excel 导入、短信、升级、统计等） |
| 数据库 | 158 个集合 Schema（含 uni-id 用户体系、uni-stat 统计、业务数据） |
| 用户认证 | uni-id（登录、注册、重置密码、手机/邮箱验证） |
| 样式 | SCSS + 双主题（默认蓝 / 绿柔） |

## 快速开始

```bash
# 安装依赖
npm install

# 运行到 H5（PC 浏览器）
npx vue-cli-service uni-build --platform h5

# 运行到微信小程序
npx vue-cli-service uni-build --platform mp-weixin
```

开发推荐使用 **HBuilderX** 打开项目，内置 uni-app 编译支持和 uniCloud 管理功能。

## 数据库初始化

项目包含完整的数据库初始化数据（`uniCloud-alipay/database/db_init.json`），在 uniCloud 控制台初始化数据库后即可使用。

## 定时任务

- **maintenance-alert-cron** — 定时扫描保养计划，自动生成保养到期提醒（报警提醒模块），支持提前 N 天提醒和逾期自动标记

## 关联项目

本项目与同级目录下的 **[device](https://github.com/anomalyco/device)** 移动端 App 共用同一 uniCloud 数据库和云函数：

| 项目 | 模板 | 定位 | 用户 |
|------|------|------|------|
| **neihao-web**（本仓库） | uni-admin | 管理后台 Web 端 | 管理员 |
| **device** | uni-starter | 移动端 App（H5/App/小程序） | 普通用户/医护人员 |

**业务场景：** device 端用户扫码查看设备、发起报修 → neihao-web 管理员处理维修流程；设备台账数据双向同步。
